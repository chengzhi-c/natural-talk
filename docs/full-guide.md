# Natural Talk Article — 文章去 AI 味完全指南

> 本文件为阅读参考（规则唯一源：`core/rules.yaml`），勿整体注入 context；需要注入请用 `templates/` 下的文件。
> 和对话版的区别：文章需要结构，删的是空洞和模板，不是结构本身。文笔 = 信息密度 + 节奏呼吸 + 具体动词。

## 阅读说明

- 本文件删的是空洞/模板/表演式结构，不是结构本身；好文章有标题、有开头、有层次。
- 文笔定义：**信息密度**（开头100字有数字/动词/实体名词）+ **节奏呼吸**（段落功能多样）+ **具体动词**（`是/有/做/提/改/查/跑`）。
- 分级：原则层（绝对）+ 表达层（弹性，上限500字基准，**路标固定2**其余按比例放宽）。

## 1. 原则（绝对，无例外）

### 1.1 不编造（尤其不编数据和案例）
不知道就说不知道；不编造时需给出可靠来源或删掉归因。文章里编造数据比聊天更危险。

### 1.2 不评判人
不做心理判断，不给身份夸奖；只评价事。

### 1.3 不装机器人
禁"作为AI/训练截止/希望帮助"；问身份除外。

> 身份披露例外：用户直接问及时如实简短回答。

## 2. 铁律

- `不是X而是Y / 不仅仅X而是Y / 不在于X而在于Y` → 直接说Y
- `与其X不如Y / 与其说X不如说Y / 看似X实则Y / 表面X实际Y` → 直接说Y
- `很久…久到… / 很远…远到…` → 给具体时间/距离
- 连续动作一句写完：`他抬起手然后伸出食指接着按下按钮` → `他伸手按下按钮`（仅紧张/暧昧/恐惧/受伤可慢放）

> 角色引号内豁免：`他说"不是优化而是重构"` 不违规。

## 3. 文章三关卡 + 表达上限

### 3.1 标题：有动词或场景

| 空泛（改） | 合格（具体主张/场景） |
|---|---|
| 关于数据库优化的那些事 | 我用三个月把查询从2秒压到80毫秒 |
| Docker 入门指南 | Docker容器起不来，我追了三天 |
| 前端性能优化深度解析 | 首页加载从8秒到1.2秒，我改了什么 |
| 微服务架构的挑战与机遇 | 我们把单体拆成12个服务后悔了 |

判据：标题是否有动词或具体场景（`用/写/追/发现/解决/优化/…` 或 `\d+|月|天|秒|我|项目|线上`），无则提示"无动词无场景"。

### 3.2 开头：100字内有信息量

❌ 在当今数字化转型的大背景下，随着容器化技术的快速发展，Docker已经成为...
✅ 容器起不来，追了三天，最后是挂载目录的 SELinux 上下文不对。

实现：命中 `在当今/随着/的背景下/众所周知/你有没有想过` 且 `密度<0.15` 才判；密度= (数字+动词+实体名词)/总长，已含信息则豁免。

### 3.3 结尾：收在具体处

禁 `让我们/共同/携手/未来可期/展望/希望对你有所启发`（尾部150字扫）。合格结尾：
- 收在具体建议：先按上面三步查一遍；还是不行贴日志。
- 收在具体问题：你现在遇到的是哪种情况？
- 就此打住：最后一段讲完技术点，不另起收尾段。

### 3.4 表达上限

| 规则 | 上限 | 说明 |
|---|---|---|
| 标题空泛 | 0 个 | 见3.1 |
| 空泛引入 | 0 处 | 开头100字内 |
| 设问钩子 | ≤1 次/全文 | `你有没有想过/你知道吗` |
| 协作口吻 | ≤1 次 | 作为AI/希望帮助/好问题 |
| 讲义腔 | ≤1 次 | 让我来/首先其次/综上 |
| 路标词 | ≤2 次（固定） | 值得注意/事实上/归根结底 |
| 破折号 | ≤2 次/500字 | 仅悬念/未说完，其余用逗号句号 |
| 感叹号 | ≤3 次/500字 |  |
| 强行升华 | 0 处 | 见3.3 |
| 加粗 | ≤1 处/段 |  |
| 三点并列 | 仅提示 | 方差<400且结构一致→疑似凑结构 |

*路标固定2不随篇幅放宽；破折号/感叹号/高频词按 500字比例。*

## 4. 文章腔检测清单

### 4.1 空泛标题（词表+判据，两栏对比）
空泛词：`的那些事/那些事/深度好文/科普一下/必须知道/详解/全面解析`；英文 `everything you need to know/comprehensive guide`。纯名词堆砌无动词→提示"加动词或场景"。

### 4.2 空泛引入（before/after段落对比）
同3.2。密度<0.15 且命中 `在当今/随着` → 违规；密度≥0.15 → 豁免警告。

### 4.3 结构模板（铁律公式）
- 讲义腔：`首先…其次…最后…（空框架时）/ 综上所述/由此可见`
- 三点并列：`三个核心维度/四大趋势` → 删编号后仍完整→拆；`常见的有三种情况`→保留。方差<400且结构一致（都有 `**…：`）→ 仅提示。

### 4.4 过渡句模板（新增，禁用/替代表格）
| 禁用 | 替代 |
|---|---|
| 说到...就不得不提 | 直接开始下一个话题 |
| 提到...自然要说 | 用具体事实桥接 |
| 那么，X到底是什么呢？让我们来看看 | 直接定义X是什么 |
| 接下来让我们/下面我们就来 | 不预告动作，直接说内容 |
| having said that / with that in mind | 删 |

### 4.5 段尾总结句堆砌（新增，量化上限）
模式：`由此可见…$/因此我们需要…$/这也是为什么…$/总之…$/可见…至关重要`；全文>2处→提示。人类作者以细节/例子收段，不每段都结论。

### 4.6 虚假归因（新增，三列表格）
| 原文 | 问题 | 修法 |
|---|---|---|
| 研究表明70%开发者用容器 | 无来源伪精确 | 删或给来源：Stack Overflow 2023调查 70% |
| 据专家介绍将持续增长 | 专家是谁 | 删或点名机构/论文 |
| 根据最新数据显示达数十亿 | 哪份数据 | 给年份/机构/报告名 |

检测：`研究表明/据专家/根据最新数据/有数据表明` 无紧邻年份/机构/论文名→违规（high）。

### 4.7 冗余复述（新增，内联示例）
`性能提升3倍。换句话说，速度变成三倍。` → 同义重复→删后句。`这是O(n)算法。换句话说，数据翻倍时间翻倍。`→ 后句补充信息→保留。触发词 `换句话说/也就是说/简单来说` 仅提示。

### 4.8 连接词密度（新增，高亮）
`然而/因此/不过/但是/同时/此外/另外/与此同时` 每500字≤4个。高亮一段堆砌示例：`…然而…此外…因此…不过…同时…`→改用语义衔接。

### 4.9 表演式标点与强调（量化规则）
破折号仅悬念/未说完可用；每段加粗≤1处；表情符号仅明确要求时；`一动作一句` 同铁律。

### 4.10 语言痕迹（共享 Tier5）
虚假主语 `数据告诉我们/体现了`；AI高频词 `crucial/pivotal/landscape`；黑话 `赋能/闭环/底层逻辑`；模糊叠加 `可能或许`。

### 4.11 强行升华结尾（词表）
尾部150字禁 `让我们/共同探索/携手/未来可期/希望对你有所启发`；结尾与开头重合率>0.4→疑似回扣式收尾。

## 5. 正确做法（7支柱，各不同展示）

**5.1 标题即主张** 左右两栏（见3.1）
**5.2 开头直入** 段落对比：`在当今…` 三段铺垫 vs `容器起不来，追了三天…` 两段直入
**5.3 段落呼吸** 结构图示：事实段→举例段→转折段→一句话段；禁3段同构（CV<0.25 仅提示）
**5.4 具体化** 替换表格：`该方案体现品牌价值` → `登录从3秒到0.8秒`
**5.5 有边界** 两栏能说/不能说：`听起来很难` vs `我完全理解你的感受`
**5.6 结尾收具体** 三种合格示例：具体建议/具体问题/就此打住（见3.3）
**5.7 保持主题** 短例：`A更快，但B也有优点…` → `A快。你做大型项目再考虑B。`

## 6. 豁免与防矫枉

真操作步骤可用"首先其次"；内容所需三点保留；自然收尾允许；长文必须展开；fiction默认关；全文详见 `docs/misjudgments-article.md`。

## 7. 适用与不适用 + fiction 开关

**适用**：技术博客/教程/复盘/观点文/长文/专栏。
**不适用**：学术论文/公文/法律/营销/演讲稿 让位。

**fiction** 默认关；仅 `小说/故事/扮演/同人/情感向` 触发时开：
- 放松：破折号6 / 感叹号6 / 铁律关 / 连接词/节间不对称关
- 新增：精确数字可感官化（`5分钟→过了一会儿`）、情感外化（`她很难过→她把水杯端起又放下`）
- 开启：`python scripts/check.py --article --fiction "标题" 正文.md`

## 8. 语言特定规则

**中文**：空泛标题词 `的那些事/指南/详解`；引入 `在当今/随着`；升华 `让我们/共同/展望`；黑话 `赋能/闭环`。
**英文**：标题 `Everything You Need to Know`；引入 `In today's rapidly evolving…`；结尾 `let us together/looking forward`；高频词 `crucial/pivotal`。
