# Natural Talk Article - 自检清单

可打印版，写完快速检查。

---

## 硬性检查（原则层，必须通过）

### 1. 标题检查
- [ ] 标题是不是空泛名词短语？（"关于X的那些事" / "X的三大维度" / "深度好文"）
  - **修法**：换成具体主张或具体场景
  - **示例**："关于数据库优化的那些事" → "我用三个月把查询性能提了十倍"

### 2. 开头检查
- [ ] 开头 100 字内有没有传递新信息？
  - **修法**：删掉"在当今""随着""众所周知""你有没有想过"
  - **示例**："在当今数字化转型的大背景下..." → "容器起不来，我追了三天"

### 3. 编造检查
- [ ] 有没有编造具体数字、来源、案例？
  - **修法**：删掉或标明不确定
  - **注意**：文章里编造数据比聊天里更危险，因为看起来更"正式"
  - **示例**："15-20% 的市场份额" → 删掉（如果没有来源）

### 4. 结尾检查
- [ ] 结尾是不是强行升华？（"让我们""共同""展望""启发"）
  - **修法**：收在具体建议、具体问题、具体画面上，或者就此打住
  - **示例**："让我们共同探索..." → "先按上面三步试一遍，还是不行把日志贴出来"

### 5. 越界评判
- [ ] 有没有评判对方（"你很敏感" / "你问得好"）？
  - **修法**：只回应内容

## 弹性检查（表达层，按各自上限）

### 6. 设问钩子（全文最多 1 次）
- [ ] 有没有"你有没有想过" / "为什么总是" / "你知道吗"？
  - **上限**：全文最多 1 次
  - **修法**：删掉，直接说内容

### 7. 协作口吻（全文最多 1 次）
- [ ] 有没有"作为AI" / "希望帮助你" / "好问题"？
  - **上限**：全文最多 1 次
  - **修法**：删掉，直接回答内容

### 8. 讲义腔（全文最多 1 次）
- [ ] 有没有"让我来" / "接下来我们" / "综上所述"？
  - **上限**：全文最多 1 次
  - **修法**：删掉预告，直接说内容

### 9. 路标词（全文不超过 2 次）
- [ ] 有没有"值得注意" / "综上所述" / "事实上" / "归根结底"？
  - **上限**：全文不超过 2 个
  - **修法**：删掉路标词，让信息自然展开

### 10. 开场白（第一段就要有信息量）
- [ ] 第一段是不是实质内容？
  - **修法**：删掉铺垫

### 11. 破折号（全文不超过 2 次，仅用于未说完/延长/悬念）
- [ ] 有没有 em dash (—) 或 en dash (–)？
  - **上限**：全文不超过 2 个，且只用于未说完的话、延长或悬念，其余用逗号或句号
  - **注意**：文章里破折号容易被用来制造"顿悟感"——"——结果是零"，仅悬念时可用
  - **修法**：改用句号、逗号、冒号或括号

### 12. 加粗（每段最多 1 处）
- [ ] 有没有一段里超过 1 处加粗？
  - **修法**：删掉多余的加粗

## 结构检查（文章特有）

### 13. 三点并列（疑似仅提示）
- [ ] 三点是内容所需，还是为凑结构？
  - **判据**：删掉编号后内容是否仍然自然完整；仅提示，不计违规
  - **附加判据**：三项长度是否大致相等、结构是否几乎一样？是 → 大概率是凑的，试试删编号读一遍
  - **示例**：内容所需（"常见的有三种情况"）保留；"三个核心维度" 提示凑结构

### 14. 段落同构
- [ ] 连续 3 段以上是否都是同一结构（"观点+解释+小结"）？
  - **修法**：打破对称，让段落功能多样（事实、举例、转折、收束）

### 15. 节奏
- [ ] 句子是不是都一样长？
  - **修法**：长短交替
  - **示例**：拆分长句或合并短句

### 16. 虚假主语
- [ ] 有没有"数据告诉我们" / "问题变成了"？
  - **修法**：改用真实主语
  - **示例**："数据显示了显著提升" → "数据显示提升了 30%"

### 17. 动作一句
- [ ] 有没有连续动作被拆成多步？（`抬起手然后伸出食指接着按下按钮`）
  - **修法**：一个动作尽量一句话（`伸手按下按钮`）；仅紧张/暧昧/恐惧/受伤需慢放时可拆解
  - **提示**：此项仅提示，不计违规

### 18. 铁律（删否定留肯定）
- [ ] 有没有"不是…而是" / "与其…不如…" / "很久…久到…"？
  - **修法**：删否定留肯定，直接说Y；角色引号内除外
  - **示例**：`不是优化而是重构→重构`；`等了很久久到忘记→等了三周`；`"不是…而是"`在引号内可保留

## 文章版三测试

1. **删除测试**：删掉这个词/段，内容是否仍然完整？
2. **读给别人听测试**：读给一个朋友听，他会尴尬吗？
3. **实质测试**：这段传递了新信息，还是只为凑结构？

## 常见误判速查（防矫枉过正）

### 不违规的情况

✅ **真实分步操作可以用"首先/其次"**
- "首先备份数据，其次关闭服务，最后执行迁移"
- 判断标准：是实际操作步骤，不是空框架预告

✅ **内容所需的三点不违规**
- "常见的有三种情况：端口冲突、镜像拉取失败、权限不够"
- 判断标准：删掉编号后内容仍然自然完整

✅ **文章可以有结尾段**
- "先按上面三步试一遍。还是起不来的话，把日志贴出来。"
- 判断标准：收在具体处，不是强行升华

✅ **复杂问题必须展开**
- "讲讲 MySQL 索引的原理，详细一点" → 500-2000 字深入解释
- 判断标准：该展开的必须展开，"直接"不等于"短"

✅ **标题可以长**
- "我用三个月把查询性能提了十倍" —— 长，但是具体
- 判断标准：看信息量，不看字数

✅ **真实共情允许**
- "项目上线第二天崩了。查了一晚，发现是配置文件里少了一个逗号。"
- 判断标准：真实的情绪回应，不是表演

### 三个快速判断法

1. **删除测试**：删掉这个词/段，内容是否仍然完整？是 → 可删；否 → 保留
2. **读给别人听测试**：读给一个朋友听，他会尴尬吗？不会 → 保留；会 → 改
3. **实质测试**：传递新信息还是凑结构？新信息 → 保留；凑结构 → 删

**记住**：规则让文章更像人写的，不是让你变成删除机器。

## 三秒记忆口诀

**三不说**：
- 不说空泛标题
- 不说空泛引入
- 不说强行升华

**三要做**：
- 标题是主张
- 开头有信息量
- 结尾收在具体处

**一个标准**：读给别人听，会尴尬吗？

---

**核心理念**：文章像人写的，不套模板。

**终极标准**：删掉空洞的开头结尾后，内容仍然完整 + 读起来不尴尬。
