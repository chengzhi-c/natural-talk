# 自查

规则写在 `SKILL.md` 和 `templates/*.txt` 里，运行时直接读。没有自动校验脚本，
因为同一个词在不同语境有对有错："至关重要"在总结里是废话，在对比两个方案时是判断；
五个比喻各管一件事是好文笔，五个都夸同一件事才是毛病。正则数得出次数，读不出
语境，既误报正常写法，又漏掉换个字就绕过的违规。判断交给模型和人。

唯一值得跑的是真实生成评测，拿模型的实际输出看规则咬不咬得住：

```bash
python scripts/eval-fiction.py --no-baseline   # fiction 模板生成，人工对着下面清单判
python scripts/eval-llm.py                     # 对话场景成对取样（带 skill / 中性）
python scripts/eval-judge.py                   # 读上一步产物，多裁判盲评谁更像真人
```

三个脚本都要 `OPENAI_API_KEY`，可用 `OPENAI_BASE_URL` 和 `OPENAI_MODEL` 换端点与模型。
`eval-judge` 只吃 `eval-llm` 的产物（`benchmarks/eval-*.json`）；`eval-fiction` 另写
`fiction-*.json`，字段不同，故意不进盲评：比喻质地和感知顺序判不了投票，得人读。

## 单段自查

写完一段，对着清单逐条读自己的输出。对话场景用
`templates/system-prompt-standard.txt` 结尾的自检项，fiction 用下面五条：

1. 每个比喻的喻体能不能看见？复现时换了属性没有？空泛的、原地重复的砍掉
2. 搜一遍"而是"：凡"不是X而是Y / 没有X而是Y / 不是X，是Y"，删否定留肯定，直接说 Y（角色台词除外）。
   搜"不是"会漏掉换否定词的变体（实测漏例：没有绝对的"更好"，而是要看你的目标）
3. 有没有哪句在替读者下结论，或让角色把事想明白了？改成动作，或让判断落空
4. 连续段落是不是长得太像？打乱一个
5. 通篇读一遍：像一个人坐在那里写的，还是像一台机器在组装的？

### 怎么算过

逐条指着具体的字说，不要答"符合"。第 1 条要数出每个比喻各自管的是哪个属性，
第 4 条要说出哪一句最像机器。凭整体感觉过一遍等于没查。

第 3 条有两种漏法：作者出面总结（"他终于明白了"），以及让角色自己把事想通。
后者更难发现，因为它读起来像人物成长，实际是把张力提前结清。

最难查的是自己刚写下的那句。写的时候顺着那个语势，读的时候也顺着它。

## 词表只拦字面，不拦动作（对话场景实测）

五题成对取样（同模型同题，唯一变量是 system prompt）的结果：Tier1/2/4/5 字面命中
带 skill 全部为 0，基线 8 处；平均长度 652 字压到 273 字。但两处漏执行说明词表的
边界在哪：

情感题里，基线写"你的感受都是完全正常的"（Tier4 原词），带 skill 写"这段时间，
难受就是正常的"。做的是同一件事：替对方认证情绪。词表拦住了那个字符串，没拦住
那个动作。**判 Tier4 要看这句在替谁下结论，不要搜词。** 换个说法就绕过的规则，
只靠词表永远追不上。

否定-肯定的漏例同源：基线开头"其实没有绝对的『更好』，而是要看你的目标"，
搜"不是"搜不到。所以自检第 2 条现在搜"而是"。

## 模型越干净，词表越测不出东西（跨厂商实测）

换一个本身就不写 AI 腔的模型，Tier1/2/5 与否定-肯定的字面命中会在两臂同时归零。
这时候拿词表去比,得到的是"没有差别",而差别其实在别处:您/你混用、每段加粗、
尾部邀约、替对方下结论、层面维度堆叠、答案长度。实测同题同模型只换 system prompt:
加粗 6 vs 12,尾邀 0 vs 3,评判越界 0 vs 3,层面类 0 vs 4,您 0 vs 6。

所以探针报 0 的第一反应不是"两边都合规",是"这根探针在这个模型上没有量程"。
先读原文找出差在哪,再照那个维度重新测。写探针前先拿已知正例咬一遍，
咬不住的探针不要用来下结论。

fiction 通路上词表的实际覆盖面只有比喻标记词（像/象/仿佛/宛如/如同/似）。
装置层那五条没有任何字面特征，只能读。

## 已知的薄弱处

三类违规反复漏网，查的时候多花点力气。

**"不是X而是Y"及变体。** 写进红线也照样漏，因为它读起来像在强调重点，语势很顺。
所以第 2 条给的是机械做法：搜"不是"逐个看，不靠语感判断。删否定留肯定之后句子
普遍更短更硬。

**重复修饰同一属性的比喻。** 数量合法不等于合格。两个比喻都在写声音的质地，
第二个就是废的，跟总共有几个比喻无关。

判空泛喻体别看"像…什么"这个字面。"床单胀起来又瘪下去，像什么东西在喘气"的喻体
是看得见的床单，合格；"像在确认什么，又好像没有"的喻体是个心理状态，还把同一个
属性修饰了两遍，才是要删的。看喻体能不能被眼睛看见，不看句子里有没有"什么"。

**判断落地。** 内心描写现在不限量，代价是容易顺手给个答案：角色问"她算是朋友吗"，下一句就答了。问出的问题原样留着，比答掉难写。

**破折号用在补充说明上。** 次数合规不等于用对。跨模型实测两处都在 ≤2 之内，
但两处都是"上手阻力小——模板语法接近 HTML"这类补充说明，规则给的用途是悬念或
话没说完，补充说明该写成逗号。查的时候不要只数个数，要看每一处破折号后面那半句
是不是话没说完；是解释、是展开、是并列的，换标点。

**景物独占段落。** 范文里景物连续不超过两句就被人物动作打断。写起来容易一路铺
下去，四五句纯景，读着像风景明信片。

这三类都数不出来：比喻个数合法，也数不出"哪几句是纯景"。自检项要对齐红线
逐条走，不能只挑好查的查。

## 改规则

`core/rules.yaml` 是给人读的规则总表，运行时不读它。真正进 context 的是
`SKILL.md` 和 `templates/*.txt`。改规则必须改这两处，只改 rules.yaml 不生效。

改完必须实际生成一段验证：规则真的咬住了，且没伤到正常写法。
